# Web 引擎 Benchmark

测试日期：2026-09-20

## 测试目标

Web UI 每个落子点都要展示独立估值，因此这里测试的是“空棋盘、固定深度 9、返回全部 25 个候选”的完整分析路径。它比对局只取最佳点的搜索工作量更大，不能直接与 `minimax/BENCHMARK.md` 中的 0.647 秒最佳点指标混用。

## 环境

- CPU：Apple M4 Pro
- 系统：Darwin 27.0.0 arm64
- Native：Apple clang 21，`-std=c++17 -O3 -march=native -flto -DNDEBUG`
- WASM：Emscripten 6.0.9，`-O3 -flto -DNDEBUG`
- 每项运行 3 次，统计引擎内部搜索时间，不包含进程启动和 UI 渲染

## 深度 9 结果

| 运行时 | 单步平均 | 3 次样本 | 节点 | 最佳点 | 候选数 |
|---|---:|---|---:|---:|---:|
| Native C++ | 2304.627 ms | 2326.848 / 2306.353 / 2280.679 ms | 6,385,873 | 12（中心） | 25 |
| WebAssembly | 2396.866 ms | 2409.319 / 2394.661 / 2386.618 ms | 6,385,873 | 12（中心） | 25 |

WASM 是 Native 的 **1.040×**，即约慢 **4.0%**；双方最佳点、分数（1130）、节点数和全部候选数一致。当前回归门槛为 WASM 不超过 Native 的 2×。

## UI 的默认单步时长

- 快棋：每步预算约 120 ms；
- 标准：每步预算约 400 ms；
- 深思：固定深度 9，空棋盘完整候选分析约 2.40 s；中盘耗时取决于强制胜负线和局面对称性。

## 复现

```bash
cd web
pnpm install
pnpm benchmark:engine
```

脚本会重新构建 WASM 和 Native 基准程序，分别运行 3 次，并校验最佳点、分数和候选数在各次运行中一致；WASM/Native 超过 2× 时以非零状态退出。
